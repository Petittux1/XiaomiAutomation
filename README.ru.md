# XiaomiAutomation

[中文](README.md) · [English](README.en.md) · [Français](README.fr.md)

Модуль автоматизации на базе root (KSU / Magisk) для **Xiaomi 17 Pro / HyperOS 4**. Он даёт планировщик с несколькими профилями, запись и воспроизведение действий в любом приложении, а также встроенную задачу ежедневного «полива» в ICBC (ICBC Daily Watering).

Работает за счёт **прямого управления через root** (`screencap` / `getevent` / `sendevent`) — без служб доступности, Xposed, хуков и инъекций через `input`.

## Возможности

- Встроенный профиль «ежедневный полив ICBC» запускается каждый день в `07:30` по умолчанию; его также можно запустить вручную и при первом открытии ICBC за день.
- Независимое расписание для каждого профиля: своё время, флаг включения, целевой пакет и последовательность действий.
- Запись с привязкой к приложению: запись начинается, когда вы переключились на целевое приложение, приостанавливается при выходе и возобновляется при возвращении; она также приостанавливается при заблокированном или погасшем экране.
- «Голая» запись: если имя пакета пустое, запись идёт с включённого экрана, а системные свайпы по краям и снизу отфильтровываются по правилам.
- При воспроизведении модуль сам будит экран, разблокирует его, запускает целевое приложение и подтверждает его на переднем плане, а затем восстанавливает блокировку ориентации, режим постоянного включения и таймаут экрана.
- **Очистка фоновых процессов после выполнения**: по окончании задачи целевое приложение закрывается через `am force-stop`, чтобы не держать память, и следующая задача стартует с чистого состояния. Есть общий переключатель и отдельный для каждой задачи.
- **Многоязычный WebUI**: 中文 / English / Français / Русский, переключается в правом верхнем углу; выбор запоминается.
- **Поддержка нескольких устройств**: слой профиля устройства позволяет настроить размер экрана, ID дисплея и раскладку цифровой клавиатуры на экране блокировки для каждой модели — тогда запись, воспроизведение и разблокировка по PIN работают и на других телефонах с HyperOS 4. Измеренная базовая конфигурация Xiaomi 17 Pro сохраняется без изменений и не затрагивается.
- **WebUI обновляется вместе с модулем**: ресурсы несут метку версии, кэширование отключено, а сам WebUI умеет сам обнаружить устаревший документ и перезагрузить его — переустанавливать модуль не нужно.
- PIN записывается только в локальную конфигурацию и никогда не появляется в статусе, журнале или исходном коде.

## Требования

Модуль использует только стандартные точки входа `customize.sh` + `service.sh`: **без Zygisk, без изменений в `/system`, без metamodule**. Поэтому планировщик, запись/воспроизведение и авторазблокировка по PIN работают и под Magisk / APatch.

WebUI — тоже **не только под KernelSU**. В APatch веб-интерфейс модулей появился ещё в сборке 10568, и он делает ровно то же, что KernelSU: отдаёт `webroot/` с `https://mui.kernelsu.org` и внедряет глобальный объект **с тем же именем** `ksu` — именно с ним общается `kernelsu.js` этого модуля. Значит, на APatch WebUI работает без единой правки. То же верно для форков KernelSU (KernelSU Next, SukiSU Ultra).

Magisk — единственное исключение: в исходниках Magisk **нет вообще никакого кода WebView** (не «не реализовано», а просто нет такой возможности), поэтому сам он `webroot/` не отрисует. Чтобы пользоваться WebUI там, нужна сторонняя программа-хост:

| Возможность | KernelSU / форки | APatch | Magisk |
| --- | :---: | :---: | :---: |
| Планировщик / запись / воспроизведение / авторазблокировка по PIN | ✅ | ✅ | ✅ |
| WebUI модуля | ✅ | ✅ | ✅ с KsuWebUI или MMRL |

**KsuWebUI** и **MMRL** каждый сами получают root на Magisk, а затем внедряют тот же самый глобальный объект `ksu` в `webroot/`. После установки любого из них модуль не требует вообще никаких правок, и WebUI работает как есть — именно так поступает вся экосистема на Magisk. Модуль поставляет `config.json` с `"webui-engine": "ksu"`, чтобы MMRL выбрал свой совместимый с `ksu` движок, а не WebUI X по умолчанию (его API несовместим).

> ⚠️ Оба пути работают, но **KsuWebUI надёжнее**: это отдельное приложение, которое само получает root и ни от чего не зависит. Совместимый с `ksu` движок MMRL помечен устаревшим в её зависимости WebUI X Portable с 2026-03-14 — сейчас MMRL закреплена на версии за 7 часов до этого, так что пока всё работает, но после обновления MMRL может перестать. Если так выйдет — переходите на KsuWebUI, модуль менять не нужно.

В любом окружении тем же бэкендом можно управлять из root-оболочки через `webctl.sh`:

```shsu -c 'sh /data/adb/modules/icbc_daily_water/webctl.sh status'
su -c 'sh /data/adb/modules/icbc_daily_water/webctl.sh settime 0730'
su -c 'sh /data/adb/modules/icbc_daily_water/webctl.sh trigger'      # немедленно запустить встроенную задачу
su -c 'WEBUI_PIN=123456 sh /data/adb/modules/icbc_daily_water/webctl.sh setpin'
```

PIN намеренно принимается **только через переменную окружения `WEBUI_PIN`**, но не как аргумент командной строки — чтобы открытый текст не попадал в список процессов. Последнюю команду набирайте руками в локальном терминале: не записывайте её в скрипт, алиас или чат.

Полный список подкоманд — в шапке файла: `webctl.sh status|setpin|settime|setenable|setmode|setopen|setsleep|setwatch|setcleanup|trigger[NAME]|restart|log|profiles|profile add/del/set|record start/stop/status`.

## Установка

1. Скачайте `XiaomiAutomation-v0.12.9.zip` из раздела Releases.
2. Прошейте этот zip в KernelSU / Magisk.
3. Перезагрузитесь, откройте WebUI модуля и при необходимости задайте способ разблокировки и PIN.
4. Для записываемой задачи укажите имя пакета целевого приложения; переключитесь на это приложение и нажмите «Начать запись», а по завершении — «Остановить запись».

### Обновление со старой версии

Просто прошейте новый zip поверх старого. Чтобы сохранить вашу конфигурацию и задачи, внутренние идентификаторы совместимости не изменились:

```text
id=icbc_daily_water
/data/adb/modules/icbc_daily_water
/data/adb/icbc_water
```

Не удаляйте эти каталоги и не меняйте ID модуля: ваши настройки, профили, PIN и записанные действия переносятся.

> Если после обновления WebUI выглядит устаревшим, проверьте версию в правом верхнем углу — там должно быть `v0.12.4`. Если там другая, значит установился старый пакет.

## Использование

### Встроенная задача

Задача «Ежедневный полив ICBC» создаётся при первой установке. Это скриптовый профиль, вызывающий встроенный `water.sh`, который проверяет главную страницу ICBC, нажимает вход в задачу и выполняет полив. Расписание по умолчанию — `07:30`, его можно изменить в WebUI.

### Записываемые задачи

1. Добавьте задачу в WebUI: задайте имя и имя пакета целевого приложения; если пакет оставить пустым, запишется весь включённый экран.
2. Нажмите «Начать запись» на задаче, затем переключитесь на целевое приложение.
3. Вернитесь в WebUI и нажмите «Остановить запись».
4. Проверьте число действий, затем запустите задачу сразу или дождитесь её времени.

Чтобы захватывать свайпы от края (жест «назад»), обязательно укажите имя пакета: в режиме с привязкой к приложению свайпы по краям сохраняются, а действия, сделанные в других приложениях, отбрасываются.

### Очистка фоновых процессов

Переключатель «⚙️ Прочее → Очищать фоновые процессы после выполнения» управляет тем, закрывать ли целевое приложение после каждой задачи. По умолчанию он **включён**. Он освобождает только процесс и никогда не удаляет данные, учётные записи или состояние входа.

Два исключения, о которых стоит помнить:

- **Цепочки задач в одном приложении**: если вы разбили сценарий одного приложения на несколько задач (например, первую и вторую половину), закрытие приложения после первой задачи вернёт следующую на домашний экран. Задачам *в середине* цепочки задайте «Выкл. (оставить в фоне)», а очистку оставьте только у последней задачи цепочки.
- **«Голые» задачи** (без имени пакета) не имеют однозначного целевого приложения, поэтому служба не знает, какой процесс закрыть. Такие задачи автоматически не очищаются; это указано на карточке задачи.

Переключатель «Поливать при первом открытии ICBC за день» работает по отдельному сценарию: телефон у вас в руках и ICBC открыли вы сами, поэтому модуль не выкинет вас из приложения.

### Экран блокировки и питание

Перед задачей модуль пытается разбудить и разблокировать экран — либо вслепую вводом PIN, либо свайпом вверх. Во время работы он удерживает экран включённым, а затем восстанавливает исходные блокировку ориентации, `screen_off_timeout` и режим постоянного включения. Если не удаётся подтвердить состояние блокировки, модуль безопасно прерывается, а не вводит координаты вслепую.

### Язык

Выпадающий список в правом верхнем углу переключает 中文 / English / Français / Русский; выбор сохраняется в локальном хранилище браузера. Строки журнала, команды и имена пакетов — это техническое содержимое, они не переводятся.

## Устройства и калибровка

Целевое устройство по умолчанию — Xiaomi 17 Pro. Модуль находит сенсорное устройство через `getevent -p` и пересчитывает координаты по диапазону осей сенсора.

### Перенос на другой телефон: профиль устройства

Карточка «📱 Профиль устройства» влияет ровно на три вещи: **ширину и высоту экрана, ID дисплея и раскладку цифровой клавиатуры на экране блокировки**. Именно они определяют, заработают ли запись, воспроизведение и разблокировка по PIN, а на других телефонах эти значения отличаются, поэтому им нужны свои.

- **Xiaomi 17 Pro**: в карточке уже указаны измеренные значения — **не трогайте их**. Оставьте «Включить переопределение» выключенным, и модуль будет использовать исходные значения из `water.sh` / `sched.conf`.
- **Другие модели HyperOS 4** (Xiaomi 17, 17 Pro Max, …): нажмите «🔍 Определить этот телефон», чтобы подставить `wm size` и `wm density`, проверьте числа, затем включите «Включить переопределение» и сохраните. Цифровую клавиатуру экрана блокировки определить надёжно нельзя — заполните её вручную, иначе будут использованы значения 17 Pro и понажимаются не те цифры.
- Профиль лежит в `/data/adb/icbc_water/device.conf`. `DEV_APPLY=0` (по умолчанию) означает «без переопределения, используется база 17 Pro»; переопределение включается только при `DEV_APPLY=1`. Каждое значение проходит проверку «уникальный ключ + только цифры», поэтому ошибка или повреждённый файл в худшем случае оставят переопределение неактивным — сломать процесс полива он не может.

> **Все модели, кроме Xiaomi 17 Pro, находятся в статусе «тестируется».** Разрешение, DPI и высота системных панелей влияют на вёрстку интерфейса, поэтому: **сценарий ICBC не гарантирован**; но **запись, воспроизведение и разблокировка по PIN работают нормально**. Не используйте его на основном телефоне.

### Воспроизведение действий, записанных на другом телефоне

У каждой записываемой задачи есть выпадающий список «Без масштаба / Масштабировать». Если задача была записана на телефоне с **другим разрешением** и вы хотите воспроизвести её здесь, выберите «Масштабировать» — модуль прочитает разрешение из заголовка файла и пропорционально пересчитает каждую координату. По умолчанию стоит «Без масштаба», поэтому запись и воспроизведение на одном телефоне не затрагиваются.

### Координаты сценария ICBC

Пробники пикселей и координаты сценария ICBC собраны в блоке конфигурации в начале `water.sh`. В комплекте есть вспомогательный скрипт для проверки цвета пикселей на снимке экрана:

```sh
python3 tools/px.py screen.png 216,778 518,780 746,748
```

## Файлы

| Файл | Назначение |
|---|---|
| `module.prop` | Метаданные модуля (отображаемое имя, версия, автор) |
| `service.sh` | Демон и планировщик профилей, пробуждение/разблокировка/восстановление питания, очистка после выполнения |
| `water.sh` | Встроенная бизнес-логика полива ICBC |
| `record.sh` | Ядро записи сенсорных событий |
| `replay.sh` | Ядро воспроизведения записанных действий |
| `webctl.sh` | Интерфейс команд root для WebUI |
| `webroot/` | Страница WebUI для KernelSU, скрипты и словари переводов |
| `sched.conf` | Шаблон конфигурации по умолчанию (рабочая конфигурация — в `/data/adb/icbc_water/`) |
| `device.conf` | Шаблон профиля устройства (рабочий — в `/data/adb/icbc_water/device.conf`) |
| `customize.sh` | Установка/обновление, права доступа и проверка целостности WebUI |
| `tools/px.py` | Вспомогательный скрипт калибровки по пикселям снимка экрана |
| `tools/run_once.sh` | Ручной запуск встроенного сценария ICBC |
| `tools/build_zip.sh` | Сборка прошиваемого zip из репозитория |

## Сборка из исходников

Выполните в корне репозитория:

```sh
bash tools/build_zip.sh
```

Скрипт запишет следующий файл в родительский каталог:

```text
XiaomiAutomation-v0.12.9.zip
```
